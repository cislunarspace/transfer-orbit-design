# 规格：地月空间轨道设计 GUI 功能补齐与界面美化

## Problem Statement

软件自 v4.0.0 从 PyQt 架构迁移到 Tauri 2（React + Rust + e2m2e sidecar）后，丢失了大量原有 PyQt 版本的核心能力与交互细节：
1. **参数表单残缺与错误裁剪**：`design_orbit` 由于硬编码裁剪逻辑，22 个设计参数中约 20 个在界面上不可见；`orbit_stability` 为空 schema 导致无法调用；17 个物理字段的单位切换能力丢失；所有参数的范围占位提示（≥/≤/~）、详细多行说明 Tooltip 及 15 种轨道类型的分支默认值与平动点联动全部丢失。
2. **e2m2e 工具未全部暴露**：虽然 e2m2e 提供了 14 个公开工具，但 catalog 库管理系列（参数扫描批量生成 `catalog_sweep`、教学案例包导出 `catalog_export`、标签标注 `catalog_tag`、族成员提升 `catalog_promote`、物理删除 `catalog_delete`）完全没有 UI 入口，只实现了基础的查询与拉取。
3. **工作流与辅助交互缺失**：轨道保持（`control_orbit`）缺乏从源工件注入星历与仿真时长覆盖校验的独立弹窗交互；轨道预报缺乏选中星历末态自动预填初值；转移设计（LGA）缺乏目标工件末态注入；缺少右键菜单、产物多选、计算完成自动选中以及谱系断链指示。
4. **画布核心交互退化**：惯性系（GCRS + SPICE 真实月球轨迹）与会合系切换、四投影（3D/XY/XZ/YZ/四视图）切换、绘制中心（质心/月球/L1/L2）切换整条链路缺失；时间轴拨动（飞行器与月球真实位置随物理时刻实时跟随）缺失；参数化 GIF 动画导出退化为固定的 8 秒录屏；缺失 SPICE 内核首次下载与引导向导。
5. **界面简陋缺乏设计规范**：零 CSS 文件与全局主题体系，使用原生未修饰 HTML 控件，缺乏暗黑模式、字号调节、分栏拖拽持久化以及双语（i18n）全覆盖。

## Solution

在遵守 ADR-0015 与 ADR-0016 决策的基础上，以 [docs-old-pyqt-gui-inventory.md](docs-old-pyqt-gui-inventory.md) 记录的 24 项 PyQt 功能底账为基准进行全面对齐：
1. **构建前端参数覆写层**：修复参数裁剪与联动引擎，以 e2m2e JSON Schema 为基底，叠加单位换算表（17 个字段）、Tooltip 提示表、分支默认值表和枚举译文表，完整呈现所有参数及其物理单位、范围和提示。
2. **闭环 e2m2e 14 个工具的界面分布**：中栏工具面板支持 7 个动力学工具 + `catalog_sweep`；左栏支持 `catalog_export` 导出、详情面板（标注/提升/谱系）、右键菜单（物理删除/稳定性分析）与轨道保持弹窗。
3. **恢复主画布高级可视化与时间轴**：基于 Three.js 重建坐标系切换、四投影切换、中心切换、时刻滑块时间轴及参数化动态导出，并接入 SPICE 内核引导。
4. **引入 Ant Design 5.x 实现现代化高密度 UI**：规范配色、间距与字阶，提供明/暗主题即时切换、字号设置（8–16pt）、分栏拖拽持久化与双语完整覆盖。

## User Stories

1. 作为轨道设计工程师，我想要在任务轨道设计工具中看到并填写所选轨道类型对应的全部参数（如振幅、相位、历元、积分时长、摄动力模型等），以便精确生成目标 CR3BP/星历轨道。
2. 作为轨道设计工程师，我想要在输入物理参数时自由切换单位（如振幅在 km/m/DU 间切换、时间在年/月/日/TU 间切换），以便按照不同文献或工程规范直接填入数值而无需手动换算。
3. 作为轨道设计工程师，我想要在悬停或输入参数时看到参数物理含义 Tooltip、可填范围提示（≥/≤/~）以及严格边界，以便了解参数约束避免计算发散。
4. 作为轨道设计工程师，我想要在切换轨道类型（如从 Halo 切到 DRO）或平动点（L1 切到 L2）时，表单自动填入该分支最合理的默认值并刷新可用范围，以便快速开始基准计算。
5. 作为任务规划人员，我想要在左栏选中一条轨道记录后，通过右键或详情面板直接打开「轨道保持」弹窗，自动继承该轨道的星历并进行仿真时长覆盖检查，以便安全评估站保脉冲代价。
6. 作为任务规划人员，我想要在选中一条星历轨道后切换到「轨道预报」工具时，工具自动将该轨道的末端位置速度与历元填入初值输入框，以便无缝开展后续延拓预报。
7. 作为任务规划人员，我想要在设计 LGA 月球引力辅助转移轨道时，能够从项目树直接指定目标轨道工件，以便算法自动提取末态作为引力辅助交会目标。
8. 作为科研人员，我想要右键点击任意轨道直接进行「轨道稳定性分析」，并在弹窗中查看 Floquet 乘子、稳定性指数与分岔诊断，以便评估轨道的动力学特性。
9. 作为科研人员，我想要通过「参数扫描（catalog_sweep）」工具批量生成一系列不同振幅或 Jacobi 常数的轨道族记录，以便构建稠密的任务轨道候选池。
10. 作为教学或演示人员，我想要在过滤栏筛选出特定轨道子集后点击「导出案例包」，将其打包为 zip 压缩包，以便与团队或学生分享复现。
11. 作为轨道库管理者，我想要在记录详情面板中为轨道添加教学标签（tags）和笔记（note），并将族成员提升为独立记录，以便沉淀轨道库资产。
12. 作为轨道库管理者，我想要在项目树中右键删除记录时弹出物理删除确认框，彻底清理底层磁盘文件，以便维护整洁的轨道库。
13. 作为可视化分析人员，我想要在画布上切换会合系（无量纲旋转系）与惯性系（GCRS km + SPICE 真实月球轨迹），以便直观观察飞行器在地心惯性空间与地月旋转空间的真实构型。
14. 作为可视化分析人员，我想要在画布上切换 3D、XY、XZ、YZ 投影以及 2×2 四视图网格，以便从各个主平面精确检查轨道对称性与包络。
15. 作为可视化分析人员，我想要切换绘制中心（地月质心 / 月心 / L1 / L2 对称居中），以便以特定天体或平动点为中心聚焦观察局部运动。
16. 作为可视化分析人员，我想要拖动画布下方的时间轴滑块（ET 秒 / UTC 显示），实时查看飞行器与月球在任意历史或未来时刻的瞬时位置标记，以便理解时空几何关系。
17. 作为演示汇报人员，我想要根据时间轴设置滑动窗或累计模式参数，导出带 UTC 时间戳的轨迹动画或高清静态图，以便用于论文与报告。
18. 作为新用户，我想要在首次启动且本地缺失 SPICE 内核时看到引导对话框，支持一键下载、指定已有目录或跳过，以便顺畅完成环境初始化。
19. 作为长时间工作的工程师，我想要一键切换深色（Dark Mode）与浅色主题，并调节界面字号（8–16pt），以便在不同光照环境和显示器分辨率下获得舒适的阅读体验。
20. 作为国际用户，我想要切换英文界面时所有菜单、面板、图表标注、提示与错误信息全部显示为规范英文，以便无语言障碍操作软件。

## Implementation Decisions

### 模块架构与职责划分
1. **参数表单引擎与覆写层**：
   - 彻底废除硬编码的适用字段表，改为基于 Schema 属性动态解析。
   - 建立参数覆写配置层，集中声明：17 字段单位换算字典（含精度、步长、换算倍率）、15 种轨道类型与各族的分支认知默认值表、字段多行 Tooltip 与严格范围格式化函数、整数枚举中英文映射。
   - 表单组件负责根据字段类型与覆写元数据渲染带单位选择器、前缀/后缀、范围提示与校验拦截的输入控件；提交前将显示数值逆向换算为标准物理单位。
   - 对 `orbit_stability` 等无 Schema 的工具，由表单层提供强类型自定义表单。

2. **UI 组件库与设计体系**：
   - 引入 Ant Design 5.x (`antd`) 作为核心控件库，使用 `Form`、`InputNumber`、`Select`、`Tree`、`Modal`、`Dropdown` 等高密度组件。
   - 全局接入 `ConfigProvider` 动态管理主题（`theme.defaultAlgorithm` 与 `theme.darkAlgorithm`）及全局字号派生体系，所有样式持久化于 `localStorage`。
   - 左右两栏恢复为可拖拽调整宽度的 Splitter 分栏布局，位置状态自动保存与恢复。

3. **工作流与 Catalog 工具集成**：
   - 将 `catalog_sweep` 注册为中栏生成工具。
   - 左栏过滤栏接入 `catalog_export` 导出交互（弹出路径选择与条数提示）。
   - 项目树接入右键上下文菜单系统，承载 `catalog_delete`（带二次确认 Modal）、查看稳定性分析对话框、轨道保持弹窗触发。
   - 左栏下部新增「记录详情面板」，展示谱系状态（含断链警告）、Jacobi 与振幅摘要，并提供 `catalog_tag` 标签笔记编辑与 `catalog_promote` 族成员提升入口。
   - 实现「轨道保持独立弹窗」，负责源记录星历/mu 注入、仿真时长覆盖公式拦截校验（((N-2) 	imes 	ext{interval} + 	ext{feedback} > 	ext{ephemeris_duration}) 提示）。

4. **Three.js 画布与时间轴增强**：
   - 画布相机与场景控制器支持 3D / XY / XZ / YZ / Quad 视图投影切换与正交/透视相机切换。
   - 场景渲染器支持会合系无量纲坐标与 GCRS 惯性系 km 坐标双重转换，惯性系下动态通过 SPICE 采样绘制真实月球轨迹与地心原点。
   - 增加以质心、月心、L1、L2 为锚点的平移居中变换。
   - 在画布下方实现时间轴组件，基于可见星历产物的时间交集建立时间刻度滑块（支持 10Hz 拖动节流），并在画布中实时插值渲染此刻飞行器与月球 marker。
   - 增强动画导出功能，支持滑动窗/累计模式与 UTC 时间戳水印合成。

5. **系统引导与双语全覆盖**：
   - 新增 SPICE 内核引导 Modal，集成下载进度与路径配置。
   - 彻底审查并重构 i18n 词典，清除所有硬编码中文，覆盖 100% 用户可见文本。

## Testing Decisions

### 测试原则
- **黑盒行为优先**：测试聚焦于用户可见交互与数据输入输出契约，不测试内部组件 state 实现。
- **高接缝测试**：前端在表单提交与状态合成层设置测试接缝；后端在 Rust 命令与 sidecar 帧通信层设置测试接缝。

### 核心测试集
1. **参数覆写与单位换算测试（前端 Vitest）**：
   - 验证 17 个单位字段在不同单位间切换时的数值换算、小数位截断与逆向提交标准单位的精度误差（< 1e-7）。
   - 验证 15 种轨道类型切换时分支默认值的正确填入与越界重置。
   - 验证 `design_orbit` 全部 22 个参数均能被正确挂载并参与数据收集。
2. **工作流注入与校验测试（前端 Vitest）**：
   - 验证轨道保持弹窗在仿真时长超过源星历天数时的拦截提示逻辑。
   - 验证选中星历工件时轨道预报初值与历元的正确提取与格式化。
3. **Canvas 变换与时间轴插值测试（前端 Vitest）**：
   - 验证会合系转惯性系的坐标变换矩阵与插值算法在特定历元下的输出精度。
   - 验证时间轴滑块在不同星历时间跨度下的归一化映射与边界保护。
4. **Rust 通信与 Catalog 命令测试（Rust Cargo test）**：
   - 验证 `catalog_query`、`catalog_export`、`catalog_delete` 命令在 Tauri 壳层的透传与错误信封协议。

## Out of Scope

1. e2m2e 中未正式实现的 5 个占位符工具（`transfer_search`, `low_thrust_design`, `manifold_analysis`, `low_energy_transfer`, `relative_motion`）。
2. 多窗口桌面架构（仍保持单主窗口架构）。
3. 远程 / 云端计算任务分发（仅针对本地 sidecar 运行）。
